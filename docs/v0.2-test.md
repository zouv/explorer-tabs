## 优先 2：浏览器式 Ctrl+Tab

至少三个正常标签，工具栏“Ctrl+Tab”开启。长按一次只切一个标签；需放开 Tab 再按进行下一次切换。

- [ ] 在当前 Explorer 的文件列表、地址栏和搜索框分别用 Ctrl+Tab 前进、Ctrl+Shift+Tab 后退；首尾循环。
- [ ] 切换不导航、不增删窗口；路径、选择、滚动和导航历史仍保留。
- [ ] 在宿主标签 / 工具栏有焦点时也能切换；切换后原生 Explorer 键盘操作可用（记录是否仍需点击文件区）。
- [ ] 普通 Tab / Shift+Tab、Ctrl+L、输入法、F2、复制粘贴行为不变。
- [ ] 长按 Tab 不连切；先按普通 Tab 再按 Ctrl，不应在长按期间突然切换。
- [ ] 文件菜单、右键菜单、属性 / 重命名等独立对话框前台时不切宿主标签、不吞它们的 Tab。
- [ ] 切到记事本 / 浏览器等其他程序后，Ctrl+Tab 不控制宿主；在其他程序按住 Tab 再切回来，不突然切标签。
- [ ] 关闭工具栏“Ctrl+Tab”后不接管快捷键；只剩一个正常标签时不接管 Ctrl+Tab。
- [ ] 最小化 / 还原、勾选开关、连续操作与正常退出后，其他程序的 Tab / Ctrl+Tab 不受影响。
- [ ] 顶层分组模式同样检查前进、后退和焦点；若前台转移被 Windows 拒绝，记录具体现场。

## 优先 3：异常恢复提示（不是目录重开）

仅虚拟机或可牺牲测试窗口，无未完成文件操作；不需要对重要窗口重复强杀实验。

- [ ] 嵌入模式强杀后若原 Explorer 已消失，启动同意恢复时明确显示“0 个已恢复 / N 个已消失”，列出原窗口标题；不声称现场已复原。
- [ ] 顶层分组强杀后，仍存活窗口真正恢复，结果数量与可见窗口对应。
- [ ] 有实际恢复失败时区分于“已消失”，提示记录保留；不清除未知身份记录、不接管新窗口。

1. 若任务栏、快捷键或后台行为有回归，先收敛稳定性；不扩大自动接管范围。
